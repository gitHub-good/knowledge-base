# 📐 技术方案模板

> 与 [02 设计架构评审清单](/project-development/02-design/index.md#design-review) 一一对应。适用：一个需求的技术实现方案 / 一次重构方案 / 一个小系统设计。写方案的目标：**让没参会的人也能照此实现和评审**。

```markdown
# 技术方案：<方案名称>

- 需求编号：REQ-xxx
- 作者 / 日期：xxx / YYYY-MM-DD
- 状态：草稿 / 评审中 / 已通过 / 已废弃
- 评审人：

## 🎯 1. 背景与目标
- 背景现状（现在怎么做的，痛点是什么，尽量有数据）
- 目标（做成什么样；可量化则量化：性能、覆盖、成本）
- 非目标（明确不做的事，防止范围蔓延）

## 🗺️ 2. 方案总览
- 一张架构图（至少 C4 的 Context/Container 级别，10 个元素以内）
- 一段话讲清核心思路（外行能懂）

## ⚖️ 3. 候选方案对比（关键！没有对比的方案是"通知"不是"方案"）

| 维度 | 方案 A | 方案 B |
| --- | --- | --- |
| 思路 | | |
| 开发量 | | |
| 性能 | | |
| 风险 | | |
| 可回滚/可替换性 | | |

**选择：方案 A，理由：…**（对齐选型五维度：成熟度/社区/学习成本/可替换性/运维成本）

## 🔧 4. 详细设计
### 4.1 接口设计（路径/方法/参数/响应/错误码；破坏性变更标注并升版本）
### 4.2 数据模型（表结构 DDL、索引、迁移脚本；含回滚脚本）
### 4.3 核心流程（时序图/流程图；关键分支：超时、重试、幂等、并发）
### 4.4 关键技术点（事务边界、锁策略、缓存一致性、分页策略等）

## 🛡️ 5. 非功能设计（逐项过，写"不涉及"也要写明）
- 性能目标：QPS / P95 延迟
- 容量预估：数据量增速、存储与连接估算
- 安全：鉴权、越权校验、敏感数据脱敏、限流
- 可观测：需要埋哪些指标/日志/告警
- 降级预案：依赖方挂了怎么办

## 🧪 6. 测试要点（对应 04 测试规范）
- 核心用例 / 边界 / 异常场景 / 兼容性影响面

## 🚀 7. 发布计划
- 分支与提交策略、灰度方案、回滚步骤（预计耗时）

## ⚠️ 8. 风险与开放问题
| 风险/问题 | 影响 | 对策 | 负责人 |
| --- | --- | --- | --- |

## 📎 附录
- 需求文档链接 / 相关 ADR 编号 / 参考资料
```

## ✅ 写方案自查（提交评审前）

- [ ] 覆盖需求全部验收标准（逐条对照）
- [ ] 至少 2 个候选方案的真实对比
- [ ] 接口契约完整，破坏性变更已标注
- [ ] 数据变更附带回滚脚本
- [ ] 非功能项逐条过（性能/安全/监控/降级）
- [ ] 关键决策同步登记 ADR（模板见 [adr-template](/project-development/02-design/adr-template.md)）
- [ ] 风险都有对策和负责人
