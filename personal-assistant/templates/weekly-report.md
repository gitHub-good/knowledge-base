# 📅 周报模板

> 原则：**结果导向（交付了什么，不是忙了什么）、数据说话、风险前置**。10 分钟填完，复制即用。

```markdown
# 周报 <YYYY-MM-DD ~ YYYY-MM-DD>

## 🎯 一、本周结果（按价值排序，写"交付物"不写"动作"）
- 【需求 REQ-xxx】部分退保功能：开发完成并提测，预计 X 月 X 日发布
- 【缺陷 BUG-xxx】保函编号重复：已修复上线，线上无复发（附验证数据）
- 【改进 IMP-xxx】补齐退保链路单测，模块覆盖率 62% → 85%

## 📊 二、关键数据（有则填，无则删）
- 发布 X 次 / 缺陷收敛 X 个 / 线上 P0P1 事故 0 起
- 核心接口 P95 延迟 xxx ms（环比 ±x%）

## 📆 三、下周计划（SMART：可验证、有期限）
- 完成 X 功能开发并提测（X 月 X 日前）
- 处理需求池 P1 项：xxx

## ⚠️ 四、风险与求助（需要对方决策/支援才写，别空喊）
- 【风险】第三方 A 接口尚未提供测试环境，阻塞联调 —— 已催办，若 X 日仍未就绪建议启用 Mock 方案，请确认
- 【求助】需要 DBA 协助执行 X 表索引变更（工单号 xxx）

## 💡 五、其他（可选：思考、学习、流程改进建议）
-
```

## ✅ 写作自查

- [ ] 每条"结果"能回答"所以呢？"——对项目/用户产生了什么影响
- [ ] 没有纯过程描述（"参加了 X 会议""调研了 X 框架"要写结论）
- [ ] 风险条目都有下一步动作和期望的决策
- [ ] 5 分钟内别人能读完
